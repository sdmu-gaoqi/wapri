## 修复 DragSortTable 拖拽「必须拖过头才换位」

- 用户现象：第一行拖到第二行，必须拖到第二行下面才生效。
- 根因：`@vue-dnd-kit/core` 的 `makeSortableList` 只算落点（写内部 `draft`），**不会搬 DOM**；`DragSortTableBody` 只用源数据 `rows` 渲染表格、也不用返回的 `items` 草稿，所以拖拽期间画面完全不动，落点由松手那一刻的指针位置决定（指针要越过目标行中点）。
- 修复：`const sortableList = makeSortableList(...)` 取回返回值，`isSorting = activeIndex >= 0`，`displayRows = isSorting ? sortableList.items : rows`，草稿变化时 `proTableRef.setDataSource(...)`，`isSorting` 变 false 时回写 `rows`（取消回退）。注册器 `v-for` 也改成 `displayRows`，否则 `getRowElement(index)` 取到的行和库里的 key 对不上。
- 验证方式：`.tmp` 里建了个 Vite 小实验页（alias 到 packages/*/src）+ puppeteer-core 驱动 Edge，2px 步进记录 `tr[data-dnd-placeholder]` 位置：现在指针到第 N 行中点即换位、上下行对称、拖到表格外/按 Esc 会回退，`onDragSortEnd(0,1)` 正常。
- 坑：`ProTable` 会渲染一份 `div.hidden-columns` 里的隐藏单元格，`.wa-ui-drag-sort-table__handle` 会多出一个（坐标在表格上方），写选择器要限定到 `table.el-table__body tbody tr` 里。
- `CropperUpload` 的 `sortable` 是同一底座、同样的「无草稿渲染」问题，但顺序由父级 `file-list` 控制，没在这次一起改。
- 二次返工（用户仍嫌「要拖到底」）：光渲染草稿不够，`strategy: 'vertical'` 比的是目标行**中点**，把手在行中间，所以还是要拖过整整一行。改成 `strategy: 'grid'` —— 它只要指针进到某一行就取该行下标（进一行换一行），配 `axis: 'y'`（指针 x 锁在起拖位置）横向偏移不影响判定。实测：行边界 162/202/242/282，指针 204→1、244→2、284→3，往上 280→2、240→1、200→0，对称无抖动。

## 面板真实目录写入排查（localhost 选完文件夹没落盘）

- 用户在 localhost + Edge 选完文件夹后什么都没写入。之前 mock 只实现了 `getDirectoryHandle` / `getFileHandle` / `createWritable`，真实 `FileSystemDirectoryHandle` 还有 `queryPermission` / `requestPermission`：有些浏览器 `showDirectoryPicker({ mode: 'readwrite' })` 只给读权限，直接写会静默失败或抛权限错。
- 修复：`ensureWritePermission(root)` 先 `queryPermission({ mode: 'readwrite' })`，不是 `granted` 就 `requestPermission`；两者都没有的老浏览器跳过，交给 `createWritable` 判断。拒绝时状态显示「未获得文件夹写入权限，请在权限弹窗中点「允许」」，且不写任何文件。
- `showDirectoryPicker` 加 `id: 'wapri-skills'`，让浏览器记住上次目录；按钮禁用时加 title 说明 HTTPS/localhost + Chromium 前提。
- 面板状态改成分步进度：「请在选择文件夹的弹窗里点『选择文件夹』…」→「正在确认文件夹写入权限…」→「正在读取技能文件…」→「正在写入 <dir>/ ...」→「已写入 N 个目录…」，这样能直接看出卡在哪一步；文档 FAQ 同步说明。
- 验证：mock `queryPermission → prompt`、`requestPermission → granted/denied` 两条路径。授权通过仍写 7 个文件（dotagents + Cursor）；拒绝授权状态文案正确且写入文件数为 0。文档站重建成功。
